# 文章生成工作流

## 总原则

- 默认按“意图 → 素材 → 大纲 → 草稿 → 风格调整 → 配图 → 定稿”的顺序推进。
- 如果用户明确只要某一个阶段的结果，不自动推进到下一阶段。
- 每个阶段的产物都保存在 `.blog-agent/runs/<date>-<slug>/` 中，方便回看与修改。

## 阶段与产物

| 阶段 | 主体 | 必须确认 | 建议产物 |
| --- | --- | --- | --- |
| 意图 | 用户 | 文章主旨、读者对象、表达意图 | `intent.md` |
| 素材 | 智能体 | 待补充内容条目清单 | `materials.md` |
| 大纲 | 双方 | 整体结构、各段重点、展示形式 | `outline.md` |
| 草稿 | 智能体 | 3 个版本中选哪一个继续 | `draft-v1.md` ~ `draft-v3.md` |
| 风格调整 | 用户 | 每轮改动方向是否准确 | 继续更新草稿 |
| 配图 | 双方 | 标题、图片方案、位置、生成方式 | `image-plan.md` |
| 定稿 | 双方 | 发布路径、front matter、图片链接 | `publish-checklist.md` |

## 1. 意图

目标：确认这篇文章到底想表达什么。

做法：
- 用户给完整大纲时，先复述理解，确认不要误读。
- 用户只给主题时，可通过 1-3 个问题收敛：
  - 主要想表达的判断是什么；
  - 读者是谁；
  - 更像经验总结、观点辨析、案例拆解还是趋势评论。
- 形成一句明确的“主旨句”，写入 `intent.md`。

完成标准：
- 用户认可“这篇文章的主旨”和“大致想怎么说”。

## 2. 素材

目标：补齐文章所需的事实、背景和支撑材料。

做法：
- 先列出“待补充内容条目”清单，再请用户确认条目是否正确、是否完整。
- 未经用户确认，不开始大规模补充素材。
- 需要时区分三类来源：
  1. 智能体已有知识；
  2. 公开检索结果；
  3. 用户提供或指定的材料。
- 对需要时效性的主题，记录检索时间与来源线索。
- 在 `materials.md` 中区分“原始信息”和“为文章服务的归纳”。

完成标准：
- 用户认可补充范围；
- 文章所需背景信息已经足够支撑大纲展开。

## 3. 大纲

目标：把文章逻辑搭起来。

做法：
- 用户已有逻辑时，只做补洞、排序、转场，不改写核心立场。
- 用户没有完整逻辑时，基于 `outline-templates.md` 提供 3 种结构选项。
- 对明显适合比较、分层、分阶段展示的内容，建议表格、列表、时间线或小标题分段。
- 大纲可多轮迭代，直到每一部分都说清“写什么、不写什么”。

完成标准：
- 用户确认整体结构；
- 关键段落顺序、重点与展示方式都已经明确。

## 4. 草稿

目标：把大纲和素材变成可选正文。

做法：
- 输出 3 个版本，差异要清楚，而不是同一篇的小改字句。
- 默认控制在中文 500-1000 字左右，除非用户另有要求。
- 可通过不同侧重制造版本差异，例如：
  - 版本 A：判断更直接；
  - 版本 B：过渡更平滑；
  - 版本 C：例子更多。
- 不擅自补一个“总结一下”“所以我们应该”式结尾。

完成标准：
- 用户明确选择一个版本继续，或指出如何合并版本优点。

## 5. 风格调整

目标：把文章调到用户认可的口吻与密度。

做法：
- 优先吸收用户的明确修改意见。
- 如果用户给的是例子而不是规则，先归纳出修改方向，再落实到当前文章。
- 每轮修改后，保留变更意图，避免下一轮又漂回原风格。

完成标准：
- 用户确认“这就是要发出去的文字风格”。

## 6. 配图

目标：让图片服务文章主旨，而不是仅作装饰。

做法：
- 先提标题建议与 1-3 张图片方案，再等待确认。
- 每张图要说明：想表达什么、放在哪一段附近、为什么需要它。
- 生成方式、提示词、文件命名、落地路径统一遵循 `images.md`。
- 临时图片先放在 run 目录的 `assets/` 中，最终采用后再移动到 `images/`。

完成标准：
- 用户确认标题与图片方案；
- 正文里已经补上正确的 Markdown 图片链接。

## 7. 定稿

目标：把中间产物变成可发布内容。

做法：
- 选择合适的发布目录：`_article/`、`_tips/`、`_book_review/`。
- 写入 front matter，至少包含 `title` 和 `date`。
- 把最终采用的图片复制或移动到 `images/`。
- 在 `publish-checklist.md` 记录：发布路径、图片路径、验证命令和结果。
- 完成后提示用户进行本地预览与检查。

完成标准：
- 文章和图片都已在正式目录；
- 本地检查通过；
- 用户知道下一步该如何 preview。
