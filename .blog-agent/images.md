# 配图工作说明

## 目标

图片要服务文章观点、帮助读者理解，而不是单纯“看起来更完整”。默认控制在 1-3 张。

## 工作流

1. 从已确认的大纲里提取适合视觉化的关键点；
2. 给出标题建议、1-3 张图片方案、每张图的放置位置与用途；
3. 等用户确认；
4. 再决定采用哪种方式：
   - 直接由当前模型生成；
   - 输出提示词，让用户或其他工具生成；
5. 临时文件先放到 `.blog-agent/runs/<date>-<slug>/assets/`；
6. 最终采用的图片发布到 `images/`，并回填 Markdown 链接。

## 图片方案应该包含什么

每张图至少说明：
- 想表达的观点；
- 适合放在文章哪个位置；
- 建议的画面元素；
- 风格方向（插画 / 简图 / 抽象概念图 / 对比图）；
- 是否需要文字元素。

## 生成方式约定

### 方式 A：模型直接生成
适用：当前环境有稳定的图片生成能力，且输出质量足够。

做法：
- 先保留提示词和版本说明到 `image-plan.md`；
- 生成后先存入 run 目录的 `assets/`；
- 用户确认后再移动到 `images/`。

### 方式 B：提示词移交
适用：当前环境不直接生成图片，或用户希望手动控制生成工具。

做法：
- 输出清晰提示词；
- 说明建议比例、风格、主体、避免项；
- 等用户把生成结果保存回工作区，再补文章里的图片链接。

## 提示词模版

```text
主题：
核心观点：
画面主体：
关键元素：
构图：
风格：
色调：
比例：
避免：
```

## 文件命名建议

发布图片建议使用统一命名：

```text
images/<date>-<slug>-01.png
images/<date>-<slug>-02.png
```

Markdown 引用示例：

```markdown
![](/images/2026-05-30-topic-01.png)
```

## 注意事项

- 优先使用原创插图、示意图、抽象概念图。
- 避免未经确认直接使用受版权限制的截图、品牌素材或人物肖像。
- 没有明确作用的装饰性图片宁可不要。
