# 大纲模版

当用户只有主题、主张还不够成形时，不要直接替用户写完整结论；先提供 3 种结构选项，让用户选择更接近自己想法的一种。

## 模版 A：观点拆解型

适合：用户已经有一个明确判断，但还没想好怎么展开。

结构：
1. 先点出判断或问题；
2. 解释为什么现在值得重提；
3. 用 2-3 个分论点拆开；
4. 回到实践场景，说明这对读者意味着什么。

特点：直接、清楚，适合经验总结和方法判断类文章。

## 模版 B：误区辨析型

适合：想反驳一个流行说法，或重新评价一件“大家都这么说”的事情。

结构：
1. 先摆出常见说法或误区；
2. 解释它为什么听起来有道理；
3. 指出它遗漏了什么；
4. 给出更可信的替代视角；
5. 用一个例子把替代视角落地。

特点：观点鲜明，适合批评、澄清、重新评估类文章。

## 模版 C：事件观察型

适合：主题和最近的行业事件、产品变化、趋势讨论有关。

结构：
1. 先交代触发写作的事件或现象；
2. 提取其中反复出现的模式；
3. 说明这些模式为什么值得开发者关注；
4. 回到作者自己的判断或观察重点。

特点：上下文清楚，适合趋势评论、现象分析类文章。

## 展示形式建议

| 内容特征 | 建议形式 |
| --- | --- |
| 多个方案对比 | 表格 |
| 分阶段演进 | 时间线 / 分段小标题 |
| 一组短判断 | 无序列表 |
| 需要展示反例或引用 | 引用块 |
| 一个核心案例带动全文 | 小节 + 案例拆解 |

## 使用提醒

- 这 3 个模版是帮助用户选结构，不是替用户做立场判断。
- 如果用户已经给了逻辑脉络，就不要硬套模版。
- 任何带有结论性质的最后一段，都必须经过用户确认。
