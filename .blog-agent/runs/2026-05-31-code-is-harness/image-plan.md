## 标题建议

### 方案 A
代码就是一种Harness

- 最直接，和正文核心判断一致
- 优点是明确、不绕
- 缺点是英文词保留较硬，需要接受这种技术味

### 方案 B
代码，不只是结果，也是AI的Harness

- 稍微把“反转”说得更明白
- 比 A 更像文章标题
- 缺点是比 A 稍长

### 方案 C
当我们说Harness时，我们其实也在说代码

- 更像一篇辨析文的标题
- 适合保留“新概念 -> 旧结构”的感觉
- 缺点是没有 A 那么利落

## 配图建议

### 方案 1：一张概念图
**位置：** 放在第 2 段后面（“代码其实就是最熟悉的 Harness”之后）

**想表达的内容：**
把“开放问题 -> 代码 -> 可执行结果”这个中间层画出来。

**建议画面：**
- 左边：自然语言问题 / 数据 / 模糊目标
- 中间：Code / Python / Runtime / Test 组成的中间层
- 右边：结果 / 校验 / 反馈
- 风格：简洁示意图，不要花哨

**用途：**
帮助读者一眼看懂“代码不是终点，而是中间的 Harness”这件事。

---

### 方案 2：一张对比图
**位置：** 放在“数字任务”那一段后面

**想表达的内容：**
对比两条路径：
- 直接让 LLM 给答案
- 先写代码再执行

**建议画面：**
左列：
- prompt → 直接结论
- 标注：看起来完整，但容易漂

右列：
- prompt → code → interpreter → result
- 标注：可执行、可检查、可重跑

**用途：**
更贴近正文里的报表例子，读者更容易记住。

---

### 方案 3：不配图，纯文字定稿
**适用：**
- 这篇本身已经够短
- 观点文不一定需要插图
- 如果不想让视觉元素分散判断力度，可以直接纯文字发布
