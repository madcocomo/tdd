# 文字风格与内容边界

## 默认风格

- 中文；
- 约 500-1000 字；
- 不必过度正式，但要稳定；
- 有个人判断，观点鲜明；
- 尽量具体，不说空话。

## 风格抓手

| 维度 | 建议 | 避免 |
| --- | --- | --- |
| 语气 | 像一个有经验的作者在认真说话 | 官样文章、宣传口吻 |
| 观点 | 清楚表达判断与偏好 | 两边都说、最后什么也没说 |
| 例子 | 用开发实践、真实场景、常见误区来支撑 | 大而空的抽象判断 |
| 节奏 | 段落短一些，转折清楚 | 一段塞太多信息 |
| 背景介绍 | 只补读者理解当前主旨所必需的部分 | 为凑字数堆历史资料 |

## 智能体应该主动做的改进

- 修正错别字、病句、重复表达；
- 补足必要的上下文，让不熟悉背景的读者也能跟上；
- 为分散观点补上自然转场；
- 识别逻辑断裂、偷换概念、论证跳跃并提醒或修正；
- 在不改变用户立场的前提下，提高可读性。

## 明确禁止

以下行为默认禁止，除非用户明确同意：

1. 在用户给定大纲之后额外增加总结段落；
2. 替用户观点增加结论、意义、概括或“上价值”；
3. 把背景介绍写成用户自己的主张；
4. 用空泛正确的话填满开头或结尾；
5. 为了让文章“更完整”而擅自改写用户的论证方向。

## 素材使用边界

- 用户提供的私有素材优先级高于智能体自行补充的公开背景。
- 公开检索得到的内容只能用来支撑、解释或补足，不应覆盖用户本来的中心判断。
- 当素材本身存在争议时，应把争议点说清楚，而不是替用户做结论。

## 自检问题

在提交草稿前，至少快速检查：
- 这篇文章的核心判断是否足够清楚？
- 有没有多写一个未经确认的“总结”或“升华”？
- 背景介绍是否真的服务主旨？
- 有没有可以删掉而不影响表达的空话？
- 读者能不能顺着段落自然读下去？
